# تحویل نوما، نسخهٔ ۳

این بسته برای بازبینی مستقل پروژهٔ نوما آماده می‌شود. رابط محصول انگلیسی است و این راهنما دامنه، روش اجرا و مرز شواهد را به فارسی توضیح می‌دهد. نسخهٔ فعلی روی تست‌نت NEAR کار می‌کند و سرویس پولی لازم ندارد.

## اجرا از پوشهٔ تازه

محیط لازم، Node.js نسخهٔ ۲۴ و npm است. پس از استخراج سورس، فرمان‌های زیر را در ریشهٔ پروژه اجرا کنید:

```sh
npm ci
npm run build
npm run judge
```

سپس آدرس `http://127.0.0.1:4313/trust` را باز کنید. این دستور پایگاه دادهٔ موقت می‌سازد و به کلید، نشست یا دیتابیس سازنده وصل نمی‌شود. اجرای شرکت و کارمند در این محیط با برچسب نمونه و واحد demoUSD است. توقف با Ctrl+C و اجرای دوباره، محیط تازه می‌سازد.

برای آزمون مستقل، دستورهای زیر گزارش تولید می‌کنند:

```sh
npm run doctor
npm run verify
npm run verify -- --browser --contract
```

گزارش اصلی در `artifacts/verification.json` ذخیره می‌شود. پروفایل پیش‌فرض، تست‌های API، ساخت برنامه و مسیر کامل HTTP را اجرا می‌کند. پروفایل دوم مرورگر و قرارداد را هم اجرا می‌کند. نیاز مرورگر، Chrome نصب‌شده یا Chromium ابزار Playwright است. برای نصب رایگان مرورگر می‌توان `npx playwright install chromium` را اجرا کرد.

تست قرارداد به Rust و پیش‌نیاز بومی سیستم‌عامل نیاز دارد. در ویندوز، ابزار MSVC یا LLVM-MinGW کامل قابل استفاده است. برای گزینهٔ دوم، متغیر `NUMA_NATIVE_TOOLCHAIN` را روی پوشهٔ ابزار قرار دهید؛ اجراکننده، مسیر DLLهای همان ابزار را تنظیم می‌کند. فایل exe تست را مستقیم اجرا نکنید. نبود محیط آماده به‌صورت خطای روشن گزارش می‌شود و تست اجرا‌نشده موفق محسوب نمی‌شود. این ابزارها در ZIP سورس نیستند.

## مسیر پیشنهادی داور

۱. در صفحهٔ عمومی، بخش Execution evidence را باز کنید. نسخه، وضعیت شبکه، تطبیق کد قرارداد و مرز قابلیت‌ها را ببینید. رسیدهای تاریخی را با تراکنش تازه اشتباه نگیرید.

۲. بخش Execution policy lab را باز کنید. یک حالت مجاز و هشت حالت مسدود دیده می‌شود. این بخش آزمایش مصنوعی سیاست است؛ تست‌های API و worker جداگانه عبور از مرز ارسال را بررسی می‌کنند.

۳. در Try numa، نقشهٔ ادعاها را دانلود کنید و با فایل‌های تست تطبیق دهید. مقدار امتیاز این فایل خالی است تا جای داوری مستقل را نگیرد.

۴. از صفحهٔ ورود، شخصیت شرکت را انتخاب کنید. نقش، حقوق و کارکنان را بررسی کنید؛ پرداخت را پیش‌نمایش و تأیید کنید و نتیجهٔ worker نمونه را ببینید. سپس با شخصیت کارمند، هدف پس‌انداز و تقسیم حقوق را بررسی کنید.

۵. پنل ادمین را باز کنید و از منوی NEAR testnet استفاده کنید. نقش ادمین و مسیر پنل حفظ می‌شود. ادمین اختیار برداشت وجه کارکنان ندارد.

۶. در بخش Live route preview، مسیر و آدرس‌های نمونهٔ مستند را انتخاب کنید. پاسخ امضاشدهٔ ارائه‌دهنده، حداقل دریافتی و انقضا نمایش داده می‌شود. این مسیر فقط قیمت می‌گیرد و وجهی ارسال نمی‌کند. نبود اینترنت باید خطا نشان دهد.

## تغییرهای نسخهٔ ۳

بازیابی تراکنش از حالت موفق، شکست قطعی، برگشت وجه و وضعیت نامعلوم تفکیک شده است. رسید تأییدشده قابل جایگزینی نیست. بلوک زمان آماده‌سازی، رسید قدیمی را از درخواست تازه جدا می‌کند. ویرایش مشخصات فرد، تصمیم حقوق در حال امضا را خراب نمی‌کند.

ذخیره‌سازی قرارداد به مجموعه‌های پایدار جداگانه منتقل شده تا پردازش برداشت مجبور به نوشتن تمام داده‌های شرکت‌ها و افراد نباشد. سقف قدیمی ۱۲هزار رویداد و ۲هزار برداشت مادام‌العمر حذف شده است. ظرفیت تجاری فعلی همچنان ۳۰ شرکت، ۵۰ کارمند در هر شرکت، ۲هزار تعهد، ۱۵۰۰ حساب سیاست، ۱۰ هدف در هر حساب و ۲هزار برداشت هم‌زمان در انتظار است. ذخیره‌سازی رایگان یا نامحدود ادعا نمی‌شود.

رابط موبایل، کنترل فوکوس، Escape، جدول قابل پیمایش با صفحه‌کلید، کنتراست، مسیر نامعتبر و تب‌های قابل لینک اصلاح شده‌اند. شکست دریافت شواهد، وضعیت سبز قبلی را حفظ نمی‌کند. بررسی خودکار دسترس‌پذیری جای بررسی انسانی کامل را نمی‌گیرد.

## داوری طبق قواعد جاری

طبق Q-017، بازتولید اجرا، بررسی قابلیت‌ها، گزارش ساختاریافته و امتیاز مقدماتی مطرح‌اند و تصمیم نهایی با داور انسانی است. وزن عددی رسمی و حدنصاب ۹۹ منتشر نشده است. کاربر فعال، درآمد، SLA، ممیزی مستقل یا مین‌نت شرط عددی اعلام‌شده نیستند؛ کسرهای قبلی بر این اساس کنار گذاشته شده‌اند. نتیجهٔ تست با امتیاز رسمی مسابقه برابر نیست.

[تحلیل قواعد و منابع](RULES_AND_SCREENING_V3.fa.md) و [دستور داوری مستقل](INDEPENDENT_REVIEW_PROMPT.md) داخل بسته هستند. داور دوم باید آزمایش خود را اجرا کند و به گزارش سازنده اکتفا نکند.

## کارهای ثبت که هنوز به مالک مربوط‌اند

مخزن عمومی، انتشار ویدئو در X با مشخصات رسمی مسابقه، اطلاعات واقعی تیم، رضایت، آدرس دریافت جایزه و ثبت نهایی انجام نشده‌اند. این موارد با آماده‌بودن نرم‌افزار محلی یکی نیستند. استفاده از AI و کتابخانه‌ها در README توضیح داده شده است. هیچ کلید خصوصی، دیتابیس، فایل env خصوصی یا نشست کاربر در بستهٔ تحویل قرار نمی‌گیرد.

## نتیجهٔ آزمایش این انتشار

در پروفایل نهایی، ۲۲۷ تست واحد و API، ۴۷ تست مرورگر و ۲۹ تست بومی قرارداد موفق شدند. یک آزمون خصوصی مهاجرت در اجرای عمومی عمداً کنار گذاشته شده و جداگانه پیش از ارتقا اجرا شده است. مسیر HTTP نمونه ۱۰ بررسی و مسیر تازهٔ واقعی تست‌نت ۱۳ بررسی موفق داشتند. جزئیات و مرز آزمون‌ها در [گزارش QA](QA_REPORT_V3.json) ثبت شده‌اند.

مهاجرت واقعی ۶۱ رویداد قبلی و موجودی‌ها را حفظ کرد. تست درخواست قیمت Intents امضای ارائه‌دهنده را تأیید کرد و هیچ انتقالی انجام نداد. بررسی وابستگی‌ها ۸ هشدار کم‌خطر و صفر هشدار متوسط، بالا یا بحرانی گزارش کرد.

در سه اجرای مستقلِ محیط نمونه، زمان آماده‌شدن سرویس حدود ۱٫۰۷ تا ۱٫۲۸ ثانیه بود. این اندازه‌گیری پس از نصب وابستگی‌هاست و تست فشار نیست. هنگام راه‌اندازی اصلی، یک درخواست شبکه ناموفق بود؛ اجرای بعدی worker به حالت RUNNING و حسابداری به حالت VERIFIED رسید. گزارش نهایی وضعیت runtime در بسته موجود است.
