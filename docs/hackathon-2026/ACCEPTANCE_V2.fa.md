# پذیرش افزوده‌های نسخهٔ ۲

معیارهای T01 تا T42 سند مصوب و ماتریس نسخهٔ ۱ حفظ شده‌اند. جدول زیر فقط معیارهای تازه است؛ گزارش موفقیت واقعی در `QA_REPORT_V2.json` ثبت می‌شود.

| معیار | نتیجهٔ لازم | آزمون/شاهد |
|---|---|---|
| معیار V201 | قیمت‌گیری فقط dry؛ ورودی wet، URL دلخواه و material انتقال رد شوند | `intents.test.ts`، strict schema و provider ثابت |
| معیار V202 | امضای واقعی قبول و دست‌کاری، echo نامنطبق، مبلغ نامعتبر و زمان کهنه رد شوند | fixture عمومی واقعی و SDK رسمی در `intents.test.ts` |
| معیار V203 | خطای داخلی provider با نبود مسیر یکی نشود؛ نتیجهٔ ساختگی نمایش داده نشود | تست ۴۰۰/۵۰۳ و مسیر خطای مرورگر |
| معیار V204 | API و worker پیش از dispatch کد/receiver/متد/شبکه و اختیار را بررسی کنند | `review.test.ts` و `worker-safety.test.ts`؛ BLOCK پیش از broadcast |
| معیار V205 | توقف automation حق مستقل کارمند را با همان سیاست حذف نکند | سناریوهای claim/release/withdraw و تست‌های قرارداد |
| معیار V206 | شواهد عمومی اطلاعات خصوصی tenant یا کلید ندهند؛ نبود RPC سبز نشود | تست endpoint عمومی و fixture خطای RPC |
| معیار V207 | تغییر ورودی، quote قبلی و پاسخ دیررس را بی‌اعتبار کند؛ انقضا دیده شود | `trust.spec.ts` |
| معیار V208 | ورود به صفحهٔ شواهد و برگشت، پنل ادمین را به شرکت تبدیل نکند | مسیر operator در `trust.spec.ts` و آزمون قدیمی navigation |
| معیار V209 | محیط judge داده و امضاکنندهٔ اصلی را استفاده نکند | `JUDGE_ISOLATION_SMOKE_V2.json`؛ دیتابیس قبلی بدون تغییر |
| معیار V210 | حذف حساب از فهرست ادمین، اختیار نشست موجود را رد کند | `auth.test.ts` |
| معیار V211 | فرم قیمت و شواهد در موبایل overflow نداشته باشند؛ نمونه‌آدرس تا کاتالوگ صبر کند | تست مرورگر و تصاویر واقعی موبایل |
| معیار V212 | نصب پاک از سورس بدون env خصوصی و API key اجرا شود | `CLEAN_INSTALL_SMOKE_V2.json` |

آزمایش مصنوعی سیاست جای حملهٔ زنده، تست بومی جای sandbox جامع و امضای fixture جای انتخاب انسانی کیف‌پول معرفی نشده است.
